# Requirement Input

Store new client-provided requirement material here before analysis or artifact creation.

Examples:

* Client briefs.
* Change requests.
* Ticket exports.
* Meeting notes.
* Screenshots or screenshot notes.
* Raw user stories, epics, initiatives, or requirement descriptions.
* API, data, report, workflow, or screen requests.

Rules:

* Preserve source wording where it matters.
* Do not rewrite raw input as confirmed requirement knowledge unless the user confirms it or a source clearly states it.
* Add source metadata in the file body when available: source, date, owner, channel, and open questions.
* Generated BA deliverables belong in `../output/`, not here.
